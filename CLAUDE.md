# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Dotfiles plus a two-stage, reproducible Arch Linux install for one specific machine: an Intel + NVIDIA (GTX 1050 Ti, `nvidia-580xx` AUR driver) laptop running Hyprland, hostname `akame`, user `gaddo`. There is no build, lint or test suite; the "code" is bash install scripts and config files.

## How the pieces fit

The repo is a **snapshot of the live machine**, and files move both ways:

- `install/capture.sh` (live → repo): runs `rm -rf` on each tracked repo dir and copies it fresh from `~/.config` (and `~/` for `home/`), then regenerates `install/pkglist.txt` (`pacman -Qqen`) and `install/aurlist.txt` (AUR packages listed by **pkgbase**, so split packages like `nvidia-580xx-dkms` collapse to `nvidia-580xx-utils`). The tracked items are the `CONFIG_ITEMS` / `HOME_ITEMS` arrays in the script.
- `install/02-post.sh` (repo → live): copies **every top-level entry in the repo root** into `~/.config/` except the names in its `case` exclusion (`install`, `home`, `README.md`, `CLAUDE.md`), and copies `home/.*` into `~/`. Existing targets are moved to `*.pre-setup` once.

Consequences:
- Editing a file in the repo does **not** change the running system, and the next `capture.sh` run overwrites the repo copy with whatever is in `~/.config`. When changing a config, either edit the live file under `~/.config` and capture, or edit the repo and also copy it to the live path. Check `diff -r <dir> ~/.config/<dir>` before assuming the two match.
- Any new top-level file in the repo root gets deployed to `~/.config/` unless you add it to the exclusion list in `02-post.sh`.
- To track a new config, add it to `CONFIG_ITEMS` / `HOME_ITEMS` in `capture.sh`; nothing else needs to change for it to deploy.

`install/01-base.sh` runs as root from the Arch ISO and **wipes the chosen disk** (1G EFI, `ROOT_SIZE` ext4 root (default 47G), ext4 `/home`), installs the base system and GRUB, and clones this repo to `~/source/gaddo-arch`. `02-post.sh` runs after first boot as the normal user and is meant to be safe to re-run. Do not run either script on this machine to test a change; per the README, test install-script changes in a VM.

Hardware-specific settings live in the scripts, not the configs: GRUB kernel parameters in `01-base.sh`, the NVIDIA `MODULES`/`HOOKS` written into `mkinitcpio.conf` and the NVIDIA suspend services in `02-post.sh`, and `nvidia-580xx-utils` in `aurlist.txt`.

## Config notes

- **Hyprland**: `hypr/hyprland.lua` is the maintained config (Lua API; stubs at `/usr/share/hypr/stubs/hl.meta.lua`). `hypr/hyprland.conf` is the autogenerated default kept alongside it. Autostart (`waybar`, `hyprpaper`, `hyprlock`, `hypridle`, 1Password) is in `hyprland.lua`.
- **Neovim**: AstroNvim v5 template (`nvim/lua/plugins/*.lua`, `community.lua`, `polish.lua`). `selene.toml` / `neovim.yml` configure the selene Lua linter (`selene .` from `nvim/`); `lazy-lock.json` pins plugin versions.
- **Shell**: `home/.bashrc` starts oh-my-posh with `~/.config/gaddo-omp-prompt.json` and runs `~/.config/sloth-greeting.sh`, which renders `akame-poster.ans` using colors from `tokyo-snow.theme`. That is why those root-level files deploy to `~/.config/`.
